## Draft 1 — The missing layer in Agent delivery

An Agent SDK can give you a model loop. That is not the same thing as operating
an Agent in production.

The difficult questions start after the model decides to use a tool:

- Where does the work happen, and does the workspace persist?
- Which credentials and permissions are available for this run?
- What happens when a tool fails, a session resumes, or a human needs to audit
  the result?

That is the Harness layer. MCP can connect an Agent to tools. A sandbox can
isolate a process. Neither, by itself, defines the operating lifecycle of the
Agent.

For builders, the practical takeaway is to evaluate the runtime as part of the
system—not as deployment plumbing added after the demo works. Sessions,
permissions, failure handling, audit, and replay shape the behavior users see.

SandBase Harness is our local-first approach to that operating layer. The repo is
open for inspection and experimentation:
https://github.com/sandbaseai/sandbase-harness

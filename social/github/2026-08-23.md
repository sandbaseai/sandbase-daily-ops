## SandBase Skills — evidence-led research without an account

If your Agent can already search the web, you can use `multi-source-search`
without adding another provider account. The Skill defines a bounded workflow,
source-origin tracing, an evidence ledger, and an offline validator. Preview or
install it here:

https://github.com/sandbaseai/sandbase-skills/tree/main/research/multi-source-search

The validator checks internal consistency; it does not pretend that a source is
true. That boundary is useful when an Agent's answer needs an audit trail.

## SandBase CLI — inspect before connecting

The CLI can preview its current client catalog before sign-in or configuration:

```sh
npx -y https://github.com/sandbaseai/cli/releases/download/v0.1.17/sandbaseai-cli-0.1.17.tgz catalog --json
```

That makes compatibility a checkable artifact instead of a README promise. The
release also documents the local MCP bridge and rollback path:

https://github.com/sandbaseai/cli/releases/tag/v0.1.17

## DeepSeek Harness Handbook — diagnose by boundary

When a DeepSeek Harness run fails, start by identifying the first broken
boundary—provider, tool, approval, sandbox, session, or client—rather than
reinstalling everything. The handbook's interactive Failure Router turns that
diagnosis into a small evidence bundle:

https://sandbaseai.github.io/deepseek-harness-handbook/diagnose.html

It is an independent, source-backed community handbook, not official DeepSeek
AI documentation.

## SandBase Docs — choose the smallest execution surface

The public Docs now separate the LLM Gateway, model/API run contract, reusable
Agents, and the CLI/MCP bridge. Start with the task you need to complete, then
verify the live Store schema instead of guessing a model or API identifier:

https://www.sandbase.ai/docs/

The source repository is public for corrections, broken links, and clearer
examples:

https://github.com/sandbaseai/sandbase-docs

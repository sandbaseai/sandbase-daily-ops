# SandBase Ecosystem Positioning

## The Core Message

SandBase helps agents connect to the real world.

It is an ecosystem and delivery layer where agents can discover, connect, orchestrate, and reuse external capabilities. Those capabilities can include APIs, models, MCP servers, skills, sandboxes, connectors, and Agent Services.

## Provider Relationship

Use this framing:

```text
<Provider> contributes <specific external capability>.
SandBase makes it available as a composable capability for agent workflows.
```

Good language:

- "<API> is now available through the SandBase ecosystem."
- "Agents can discover and reuse <capability> in SandBase workflows."
- "SandBase connects the capability layer to real-world agent delivery."
- "Use <Provider> alongside other capabilities in the SandBase ecosystem."

Avoid unless separately verified:

- "<Provider> is deployed on SandBase."
- "SandBase hosts <Provider>."
- "SandBase replaces <Provider>."
- "<Provider> is a SandBase product."

## What SandBase Adds

SandBase is not another isolated API wrapper. Its value is the connective tissue across the ecosystem:

- capability discovery and selection;
- agent-facing integration boundaries;
- reusable workflows and Agent Services;
- sessions, artifacts, skills, tool governance, and execution context;
- a path from individual APIs to work that can be delivered to real users.

Write only the elements that the product surface or approved facts support. Do not enumerate every layer in every post.

## Short Copy Lines

- "Connect your agent to the real world."
- "From external capabilities to connected agent workflows."
- "Bring the best APIs, models, and tools into one agent delivery layer."
- "One ecosystem for the capabilities your agent needs to get work done."

## Decisions and context changes

- Adopted the umbrella statement: SandBase turns AI capabilities into deliverable Agent workflows through an API surface, portable Skills, a CLI/MCP bridge, and a local-first Harness.
- Kept product boundaries explicit: Skills define procedure; CLI connects clients; Harness governs execution; API supplies hosted capabilities; Blog acquires and educates; Docs converts intent into successful use.
- Future automatic promotion must read `promotion-plan/master-context.md`, run the applicable audit, and append evidence here before changing shared positioning.
- Operator boundary added: `sandbase-monorepo` is inspection/feature-branch/PR only. Automation must not push directly to its main branch or trigger its production deployment. Other in-scope repositories retain their normal PR/merge/deploy authorization.

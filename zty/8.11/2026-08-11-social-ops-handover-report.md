## 1. 接管结论

`sandbase-daily-ops` 不是 SandBase 主产品代码仓库，也不是博客源码仓库。它是团队用于管理产品发布、技术内容、SEO/GEO、社媒分发和运营记录的工作仓库。

社媒运营岗位的核心职责是：

```text
开发团队发布产品能力
→ 收集并核实产品事实
→ 判断关键词、受众与内容角度
→ 生产博客及各平台原生内容
→ 完成审核、发布和搜索引擎提交
→ 记录数据并推动下一轮优化
```

当前最重要的接管动作不是马上批量发布内容，而是先补齐权限、建立最新数据基线、核实历史项目真实进度，并确认团队的审核和发布规则。

## 6. 日常工作 SOP

### 6.1 上午：信息与数据检查

1. 查看开发团队当天的模型、API、Agent、Docs 和产品更新。
2. 向开发确认正式名称、上线状态、文档链接、价格、功能边界和可公开数据。
3. 检查 AI 行业热点，判断是否与 SandBase 产品能力相关。
4. 检查 Google Search Console：点击、展现、CTR、排名、收录和错误。
5. 查看是否存在需要当天响应的产品发布或高热度选题。

### 6.2 白天：内容生产和审核

1. 写作前检查内容索引，避免重复选题。
2. 明确目标用户、搜索意图、主关键词和唯一 CTA。
3. 先生产 Blog canonical 内容，再改写为各平台原生版本。
4. EN 和 ZH 分别原生写作。
5. 每篇文章准备至少 3 张有效截图，推荐 3–5 张。
6. 检查所有事实、链接、标题、Meta、内链、图片和 CTA。
7. 由技术负责人审核技术事实，由运营/品牌负责人审核对外表述。

### 6.3 发布与分发

1. 在博客仓库执行格式检查和完整构建。
2. 通过团队确认的 GitHub 分支和 PR 流程发布。
3. 验证线上 EN/ZH 页面、封面、截图和链接。
4. 发布 LinkedIn、X、Discord、Medium、知乎等渠道版本。
5. 向 Google/Bing 提交新 URL，记录提交结果。

### 6.4 下班前记录

每日记录至少包括：

- 完成的内容和任务。
- 发布平台、URL 和时间。
- 数据变化与异常。
- 等待开发或负责人确认的事项。
- 明日计划。
- 对外反馈、用户问题和潜在线索。

## 11. GitHub 工作方式

在团队规则尚未确认前，不直接修改并推送 `main`。建议流程：

```bash
git pull --ff-only
git switch -c codex/<date>-<topic>
git status
git add <明确的文件路径>
git commit -m "docs: <简短说明>"
git push -u origin <当前分支>
```

随后创建 Pull Request，请负责人审核后合并。不要在不确认文件范围时直接使用 `git add -A`。

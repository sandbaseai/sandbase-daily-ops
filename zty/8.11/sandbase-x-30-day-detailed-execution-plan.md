> 执行周期：2026-08-11 至 2026-09-09  
> 主要语言：英文  
> 主要受众：AI Agent 开发者、AI 基础设施团队、技术创始人和平台工程师  
> 主要转化路径：X 帖子 → SandBase 官网 / Docs / Playground → API Key、产品试用、开发者对话或集成机会  
> 内容原则：所有产品、价格、兼容性、性能和客户声明必须有官方证据；没有证据就不发布。

> 启动调整：前 14 天优先执行 `zty/8.11/models-apis-mini-demo-sprint.md`，从 Models 和 APIs 的短 Demo 建立发布节奏，再进入 Agent Runtime、Sandbox、Session 和 Trace 内容。

## 1. 30 天结束时应完成什么

### 内容产出

- 发布 45–60 条英文原创帖，正常情况下每天 1–2 条。
- 发布 4 条深度 Thread，每周 1 条。
- 发布 4 个 30–60 秒真实产品 Demo，每周 1 个。
- 发布 4 次 Build in Public 周报。
- 完成至少 150 条有内容的开发者互动回复，平均每天 5–8 条。
- 建立并持续使用 3 个栏目：
  - `Runtime Reality`：生产 Agent 的真实问题。
  - `Built on SandBase`：真实工作流和产品证据。
  - `What Stops the Agent?`：权限、预算、重试、停止条件和审计。

### 结果目标

第 1 周用于建立真实基线，后续以相对增长为主：

- 第 4 周原创帖中位曝光达到第 1 周的 2 倍。
- 至少 10 条帖子的曝光达到当周中位数的 2 倍。
- 至少产生 5 次来自目标开发者的有效对话。
- 至少产生 30 次可归因的官网、Docs 或 Playground 点击。
- 至少获得 2 个开发者测试、内容联动或潜在集成机会。

粉丝数作为观察指标，不作为唯一目标。没有历史数据时，不承诺绝对增长数字。

## 2. 核心定位和传播规则

### 推荐一句话定位

> The runtime layer for production AI agents — models, sandboxes, tools, sessions, and traces in one API.

### 核心差异表达

> Connecting tools is easy. Running them safely, observably, and repeatedly in production is the hard part.

每周内容必须覆盖以下五个问题中的至少三个：

1. Agent 在哪里执行代码？
2. Agent 可以调用什么工具，权限如何限制？
3. 失败和自动重试会花多少钱？
4. 会话、文件和状态如何保留和恢复？
5. 人如何检查、暂停、复现和审计一次运行？

### 向竞品学习什么

- 学 Naïve：用视觉和完整场景展示结果。
- 学 AISA：参与热点讨论，把抽象功能变成具体痛点。
- 学 Monid：降低理解和使用门槛，一个帖子只讲一个动作。
- 不学习：无证据的夸张承诺、在无关热门帖下硬塞产品、批量复制相同回复。

## 9. 帖子发布前检查

### 事实

- [ ] 产品正式名称已经确认。
- [ ] 上线状态、价格和可用范围有官方来源。
- [ ] 数字、日期、性能和兼容性没有自行推测。
- [ ] 客户、合作和第一人称体验已获得许可。

### 内容

- [ ] 第一行能独立表达一个明确问题或观点。
- [ ] 帖子对不点击链接的读者也有价值。
- [ ] 一个帖子只设置一个 CTA。
- [ ] 没有把博客摘要直接复制成 X 帖子。
- [ ] 没有使用“最强、第一、零故障、完全自治”等无证据绝对表达。

### 视觉

- [ ] 截图没有 API Key、邮箱、客户信息或内部 URL。
- [ ] 终端文字在移动端可读。
- [ ] Demo 在前 3 秒展示任务或结果。
- [ ] 视频有字幕，不依赖声音理解。

## 10. 每日数据记录

每条主帖至少记录：

| 字段 | 记录内容 |
|---|---|

| Post URL | X 链接 |

| Pillar | Runtime / Sandbox / MCP / Routing / Session / Build in Public |

| Engagements | 总互动 |

| Link Clicks | 链接点击 |
| Qualified Replies | 目标开发者回复 |
| Leads | 试用、私信或合作线索 |
| Decision | 保留 / 重写 / 停止 / 扩大 |

## 11. 周报判断规则

### 扩大

- 连续两周高于中位曝光，并带来目标开发者互动。
- Demo、Checklist 或 Thread 带来明显点击或收藏信号。
- 创始人观点带来真实技术讨论或合作机会。

### 重写

- 有曝光但没有资料页访问、点击或有效回复。
- 技术准确，但开头抽象、没有场景或证据。
- 内容方向正确，但形式不适合移动端阅读。

### 停止

- 只发博客链接，没有 X 原生信息价值。
- 在无关热点下硬塞 SandBase。
- 对不同账号批量复制完全相同的回复。
- 使用无法证明的数据和合作背书。

## 12. 阻塞时如何处理

| 阻塞 | 当天替代方案 |
|---|---|
| 没有产品更新 | 发布技术教育、Checklist 或真实旧功能 Demo |
| 没有录屏条件 | 发布截图、trace、代码片段或架构图 |
| 产品事实未确认 | 不写产品承诺，改成行业教育内容 |
| X Analytics 未取得 | 记录公开互动和链接点击，继续申请权限 |
| Docs 链接不稳定 | 不发布转化帖，先修复落地页 |
| 热点与产品无关 | 不追热点，发布栏目内容 |
| 开发审核未完成 | 草稿保留，不抢时间发布 |

## 13. 30 天验收清单

- [ ] 账号定位、Bio、置顶帖和官网链接统一。
- [ ] 45–60 条原创帖已发布并有完整记录。
- [ ] 4 条 Thread 和 4 个真实 Demo 已发布。
- [ ] 4 份周报和 1 份最终复盘已完成。
- [ ] 胜出栏目、钩子、视觉形式和 CTA 已明确。
- [ ] 至少 5 次目标开发者有效对话已经记录。
- [ ] 官网、Docs、Playground 点击能够追踪。
- [ ] 下一阶段计划建立在真实数据上。

这份计划的重点不是让账号看起来每天都很忙，而是用连续、可验证的产品证据建立一个明确认知：SandBase 是 AI Agent 从 Demo 进入可控生产运行时所需要的基础设施层。

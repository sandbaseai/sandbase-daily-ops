# API Launch SOP

Use this playbook when a new API, provider, or Agent Service is ready to announce.

## Inputs

Collect:

- API / provider name
- Short description
- Capabilities
- First use cases
- Audience
- Docs or demo link, if available

Example:

```text
API: Exa Search
Description: AI-native web search engine that finds exact content using semantic search.
Capabilities: Web Search, Extraction, Highlights, Summary, Artifacts
Use cases: Company Research, Competitor Monitor, Lead Research, Market Map
```

## Positioning

Use this pattern:

```text
<Provider> provides <raw capability>.
SandBase turns it into a reusable Agent Service.
```

Do not make SandBase look like a thin wrapper.

## Required Outputs

Prepare:

- Blog draft
- LinkedIn post
- X / Twitter post
- Discord announcement
- 16:9 launch image

Optional:

- 4:5 mobile social image

## Channel Rules

Blog:

- Explain why the capability matters.
- Explain what the provider does.
- Explain what SandBase adds.
- Include first use cases.
- End with category direction.

LinkedIn:

- Keep it short.
- Lead with product availability.
- Use bullets for use cases.
- End with “From APIs to reusable Agent Services.”

X / Twitter:

- Single concise post by default.
- Make the capability and use cases obvious.

Discord:

- Practical, not polished.
- Tell builders what changed and how to try it.

## Image Rules

Match SandBase website:

- White background
- Subtle square grid
- Huge black sans-serif headline
- Minimal green accents
- Thin-line workflow diagram

Avoid:

- Serif headlines
- Warm beige editorial style
- Fake logos
- Fake dashboards
- Fake metrics

## Publish Checklist

- [ ] Blog draft reviewed
- [ ] LinkedIn copy reviewed
- [ ] X copy reviewed
- [ ] Discord copy reviewed
- [ ] Image text checked
- [ ] Provider/SandBase boundary is clear
- [ ] No inflated claims
- [ ] Links are valid
